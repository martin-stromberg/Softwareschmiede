## Fehlende oder unvollständige Testanforderungen

- [ ] **Betroffene bestehende Tests unvollständig — `SettingsViewModel`-Konstruktor-Erweiterung:** Der Plan behauptet „keine direkte Test-Instanziierung vorhanden" (plan.md Z. 175). Das ist falsch: `SettingsViewModelTests.CreateSut` (`src/Softwareschmiede.Tests/App/ViewModels/SettingsViewModelTests.cs` Z. 60–70) und `SettingsViewModelTests_IdePlugin.CreateSut` (`src/Softwareschmiede.Tests/App/ViewModels/SettingsViewModelTests_IdePlugin.cs` Z. 55–65) instanziieren `new SettingsViewModel(...)` mit 9 positionalen Argumenten. Zusätzlich registriert `MainWindowViewModelUpdateTestBase` (`src/Softwareschmiede.Tests/App/ViewModels/MainWindowViewModelUpdateTestBase.cs` Z. 77) `AddTransient<SettingsViewModel>` in einem Test-DI-Container **ohne** `IDialogService`; `MainWindowViewModel.NavigateToSettings` löst das ViewModel per `GetRequiredService<SettingsViewModel>()` auf (`src/Softwareschmiede.App/ViewModels/MainWindowViewModel.cs` Z. 234) und wird über `SpeichereUpdateEinstellungenUeberUiAsync` (Z. 144–155) von den Update-Tests tatsächlich durchlaufen. Sind die neuen Parameter erforderlich: Kompilierbruch in zwei Testklassen + `InvalidOperationException` bei der DI-Auflösung in den Update-Tests. Sind sie optional (`= null`): unklar, wie `KonsolenTestOeffnenCommand` mit `null`-Abhängigkeiten umgeht. Der Plan muss die Entscheidung (erforderlich vs. optional) treffen und die drei betroffenen Testartefakte in „Betroffene bestehende Tests" aufnehmen (bei erforderlichen Parametern: `CreateSut`-Signaturen erweitern + `IDialogService`-Mock im Update-Testcontainer registrieren).
- [ ] Negativer Validierungstest für `ZeitrafferSchwelleText` nicht eindeutig geplant: Die Validierungsregel (plan.md Z. 161) spezifiziert „Ungültige Eingabe → `FehlerMeldung`/Feldvalidierung, letzte gültige Schwelle bleibt aktiv" — der zugeordnete Test `WiedergabeStartenPausierenFortsetzen_SteuernSession` (Z. 281) sagt nur „`ZeitrafferSchwelleText` validiert", ohne sich auf den Negativfall (ungültige Eingabe → `FehlerMeldung`, alte Schwelle bleibt wirksam) festzulegen. Entweder dort explizit ergänzen oder als eigener Test benennen.
