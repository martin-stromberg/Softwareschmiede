**Status:** Plan lückenhaft

Die fachlichen Kernentscheidungen sind gegen den realen Code verifiziert und tragfähig: `CompositeTerminalOutputSink` + `ITerminalDiagnoseSink` lösen das Marker-Problem korrekt (`TerminalSessionService.WriteDiagnosis`, `src/Softwareschmiede/Infrastructure/Terminal/TerminalSessionService.cs` Z. 131–149, schreibt Marker über `outputSink.OnOutputChunk` Z. 143 und wird bereits *vor* `launcher.Start` aufgerufen — u. a. Z. 113 „Pipe-Backend gewählt (E2E-Testmodus)"); die `TerminalControl`-Pflichtaufrufe (`RebuildBufferFromReplay` Z. 124, `buffer.Resize` Z. 126, `session.Resize` in `OnRenderSizeChanged` Z. 311) sind im Plan korrekt adressiert; der `new Process()`-Stub für das nicht-nullable `ITerminalSession.Process` (Z. 18) passt zum bestehenden `InvalidOperationException`-Fang in `TaskDetailView.xaml.cs TryGetProcessId` (Z. 161–174); Dialog-/DI-/E2E-Konventionen (`WpfDialogService.ShowDialogAsync` Z. 181–190, `App.xaml.cs` Z. 310–311/323–324/360–374, `DialogView`-Titel-Erkennung, `HandleSaveFileDialog`-Muster in `src/Softwareschmiede.Tests/E2E/Views/TaskDetailView.cs` Z. 345 ff., `RunGeneralTests`/`RunConPtyTests`-Bündelung) sind korrekt beschrieben. ## Hinweise

- **Verifizierte Kernbehauptungen:** `ITerminalSession.Process` nicht-nullbar (`ITerminalSession.cs` Z. 18); `WriteDiagnosis` schreibt Marker über `OnOutputChunk` vor dem Launcher-Start; `TerminalControl.OnSessionChanged` (Z. 94–132) und `OnRenderSizeChanged` (Z. 301–317) Pflichtaufrufe; `KiAusfuehrungsService`-Konstruktor hat aktuell 4 Parameter (Z. 33–39), `IOptions<TerminalSessionOptions>`/`TimeProvider` sind bereits im DI-Container (`App.xaml.cs` Z. 233/311); `TestKiAusfuehrungsServiceFactory` ist die einzige Test-Construction-Site des Service; `Microsoft.Extensions.TimeProvider.Testing` ist im Testprojekt referenziert (csproj Z. 31); `SettingsView`-Tab „Allgemein" existiert (Z. 236–321); `Microsoft.Extensions.DependencyInjection`-Auflösung via `_serviceProvider.GetRequiredService` ist die etablierte Konvention (`TaskDetailViewModel` Z. 2357).
- **Deterministischer Launcher füttert keine Chunks:** `DeterministicPseudoConsoleProcessLauncher` in `TestTerminalSessionFactory` erzeugt die Session auf leeren MemoryStreams — für `StartTerminalSession_VerdrahtetRecorder` und `ExportCliReplay_SchreibtClireplayDatei` wird (wie im Plan angedeutet) ein Launcher-Double mit beschreibbarem/kontrollierbarem Output-Stream benötigt, das `OnOutputChunk` mit Test-Chunks füttert; das sollte im Plan explizit als Hilfsmethode benannt werden (neben `TestKiAusfuehrungsServiceFactory` in „Betroffene bestehende Tests").
- **`IstVollstaendig` in der UI:** Der Plan speichert das Flag im Header/Modell, sieht aber keine Anzeige im Konsolentestfenster vor — für ein Diagnosewerkzeug wäre ein Hinweis „Aufzeichnung unvollständig (Budget überschritten)" sinnvoll (z. B. im `StatusText`), damit ein abgeschnittenes Replay nicht falsch interpretiert wird.
- **Header-Konsistenz:** `CliOutputAufzeichnung.EndeUtc` ist im Modell enthalten, fehlt aber in der spezifizierten Header-Feldliste; umgekehrt fehlt eine Header-Validierung für `Cols`/`Rows` (0/korrupt → Buffer-Anlage wirft) — bei `LadeAsync` prüfen und als `InvalidDataException` melden.
- **OpenFileDialog-Automation:** `WaitForSaveDialog`/`SaveDialogCondition` (`TaskDetailView.cs` Z. 474 ff.) suchen nach „Speichern unter"/„Save As" — für den OpenFileDialog wird eine eigene Titel-Bedingung („Öffnen"/„Open") benötigt; im Plan nur implizit enthalten („analog HandleSaveFileDialog").
- **E2E-Dialog-Cleanup:** Das neue Szenario sollte den modalen Dialog im `finally` schließen (Muster `TryCloseTaskDetail`), damit ein offengebliebener „Konsolentest"-Dialog die nachfolgenden `RunGeneralTests`-Szenarien nicht blockiert.
