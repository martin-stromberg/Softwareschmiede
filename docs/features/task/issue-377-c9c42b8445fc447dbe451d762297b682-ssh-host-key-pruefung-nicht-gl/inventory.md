# Bestandsaufnahme: SSH-Host-Key-Prüfung nicht global aushebeln (Issue #377)

Analysiert wurde das `GitHubPlugin` (git-Transport, Credential-Umgebung, Remote-URL-Behandlung) und alle Aufrufer seiner git-Operationen in `src/` sowie die parallel existierende Konfiguration im `BitBucketPlugin` — bezogen auf die Anforderung in `requirement.md`, `GIT_SSH_COMMAND` und `core.sshCommand` zu entfernen und plugin-geführte git-Operationen auf HTTPS festzulegen.

## Zusammenfassung

- **Beide unsicheren Konfigurationen existieren wie beschrieben:** `GitHubPlugin.GetGitEnvironment` setzt `GIT_SSH_COMMAND=ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null` (`plugins/Softwareschmiede.Plugin.GitHub/GitHubPlugin.cs:215`), und `ConfigureGitCredentialsAsync` schreibt nach jedem Klon persistent `git config core.sshCommand` mit demselben Wert in die Arbeitskopie (`GitHubPlugin.cs:550-560`). Die Zeilenangaben aus `issue.md` (Z. 189/381) beziehen sich auf eine ältere Dateiversion.
- **Alle sieben plugin-geführten git-Pfade laufen über `GetGitEnvironment`:** `CloneRepositoryAsync`, `PushBranchAsync`, `PullAsync`, `GetRemoteBranchesAsync` (`ls-remote --heads`), `GetDefaultBranchAsync` (`ls-remote --symref`), `CheckoutPullRequestSourceAsync` (via `CheckoutPullRequestSourceCoreAsync` in `GitPluginBase`) und `ConfigureGitCredentialsAsync` selbst. `GetGhEnvironment` (nur `GH_TOKEN`) bedient ausschließlich die `gh`-CLI-Aufrufe (`issue create`, `pr create`, `pr merge`, `pr ready`).
- **HTTPS-Auth ist bereits eingerichtet und tokenlos-fail-fast:** bei vorhandenem Token setzt `AddGitHubHttpAuthHeader` `GIT_CONFIG_COUNT/KEY_0/VALUE_0` mit fest verdrahtetem Key `http.https://github.com/.extraheader` — für GitHub-Enterprise-Hosts (die `ParseEventRepository` unterstützt) würde die git-Auth damit nicht greifen. `CloneRepositoryAsync` wirft nur für HTTPS-URLs ohne Token vorab (`IsHttpsRepositoryUrl`, Z. 399-401/1043-1047); SSH-URLs (`git@host:…`, `ssh://…`) klonen heute ohne Token über den SSH-Bypass.
- **SSH-URLs werden an mehreren Stellen akzeptiert/erzeugt:** `GitRepository.RepositoryUrl` wird ohne Formatvalidierung persistiert (`ProjektService.ValidateRequiredFields`/`ResolveRepositoryUrl`, Z. 445-501); `ParseEventRepository` (`GitHubPlugin.Events.cs:397-424`) und `TryExtractRepositoryId` (`GitHubPlugin.cs:1782-1832`) akzeptieren SCP- und `ssh://`-Formate; `ParsePullRequest` fällt auf `ssh_url` zurück, wenn `clone_url` fehlt (`GitHubPlugin.cs:1015`); `GitOrchestrationService.ExtractRepositoryIdFromUrl` (Z. 403-447) löst SCP-URLs zur Repository-ID auf.
- **Bestandsbereinigung hat einen etablierten Präzedenzfall:** Issue #376 implementierte die einmalige `_netrc`-Bereinigung im `GitHubPlugin`-Konstruktor (`RemoveLegacyNetrcEntries`, Z. 276-348) mit Testseam (`netrcPath`-Parameter, `SOFTWARESCHMIEDE_NETRC_PATH`) und eigener Testklasse `GitHubPluginNetrcCleanupTests` — Vorbild für eine etwaige `core.sshCommand`-Bereinigung in Bestands-Arbeitskopien. `NormalizeRemoteUrlAsync` (Z. 448-490) normalisiert `remote.origin.url` bereits vor Push/Pull (entfernt eingebettete Legacy-Tokens), wäre der natürliche Erweiterungspunkt für eine SSH→HTTPS-Umschreibung.
- **`BitBucketPlugin` trägt denselben Bypass nur in der Prozessumgebung:** `BitBucketPlugin.GetGitEnvironment` setzt identisches `GIT_SSH_COMMAND` (`BitBucketPlugin.cs:172`), schreibt aber kein `core.sshCommand` in Arbeitskopien. Laut Anforderung Scope-Ausschluss (Offene Frage 3).
- **`GetAgentEnvironmentAsync` ist bereits sauber** (`GitHubPlugin.cs:175-190`): nur `GIT_TERMINAL_PROMPT=0`, `GH_TOKEN`, `GIT_CONFIG_*`-extraheader — kein `GIT_SSH_COMMAND`. Agenten-git-Operationen in betreuten Kopien erben den SSH-Bypass aktuell ausschließlich über das persistente `core.sshCommand` in `.git/config`.
- **Tests:** Ein Test assertiert den Bypass explizit (`CloneRepositoryAsync_OhneToken_NurTerminalPromptUndSshInEnv`, GitHubPluginTests.cs:1761-1785, klont per `git@`-URL und verlangt `env.ContainsKey("GIT_SSH_COMMAND")`); mehrere Env-Matcher prüfen `GH_TOKEN`/`GIT_CONFIG_*`/kein `NETRC`, aber noch keine `GIT_SSH_COMMAND`-Abwesenheit. Kein Test assertiert das `git config core.sshCommand`-Setzen; die Methode wird in den Clone-Tests still mit durchlaufen.

**Test-Ausgangszustand:** Regulär-Lane vollständig grün — `Softwareschmiede.Tests`: 2352 bestanden / 0 fehlgeschlagen / 3 plattformbedingt übersprungen; `Softwareschmiede.IntegrationTests`: 280/280 bestanden. OsInterface-Lanes (FlaUI-/ConPTY-E2E) nicht ausgeführt — kein feature-relevanter Test darin (kein E2E-Test referenziert `GitHubPlugin`-git-Env oder SSH; `ScmE2EGitRunner` verwirft die Env ohnehin). Details: [tests.md](inventory/tests.md).
